## 思考
AI工作流（invoke）也能干活，它和Agent（ReAct）有何区别？
很多人会混淆，反正都是AI在执行任务

## Agent 智能体
和workflow逻辑完全不一样，它不走在一条预设的轨道上，而是站在一个开放的空间里，自己去探索怎么去做（智能）。
从技术角度，一个Agent往往具备三个核心能力。

第一个能力：感知环境
通过输入文本、图像、数据来理解任务。有哪些工具可以调用，当前情况如何。如何分步骤、如何规划。
第二个能力：规划路径
不是预先定义好，而是动态去生成任务链。
第三个能力：执行行动
去调用工具，完成子任务，并不断地去调整。

## 举例
你让Agent去规划旅行，他可能会先去搜一下机票和酒店价格。再去查天气和签证需求结合你的偏好和预算去权衡方案。
整个过程，它可能走的路径和你的预期完全不同，这就是Agent的关键区别，自主性和适应性。他不会被一个固定的流程限制，而是像一个思考中的个体。所以，本质的区别在于：workflow是确定性的执行，agent是一个不确定的探索。
Workflow就好像一条高速公路，路线很清晰很固定，效率很高，但能到达既定的终点。
Agent更像一个司机，他知道要去哪儿。但可以随时改道（修路，感知环境），尝试新的路径，甚至在目的地发送变化的时候，自行调整。

所以，从产业角度，workflow 更适合流程化，重复的任务。
比如审批流程、数据清洗客服AI 
Agent更适合动态的一个角色场景。比如：复杂搜索、策略规划。
从技术栈的领域，workflow更依赖于规则，图形化编排（coze），流程引擎。Agent更依赖于大模型的推理能力和记忆能力，包括它的工具调用等。

未来我们的AI工程中将会集合Agent和Workflow的双重能力。
底层是workflow去提供稳定性和可控性。上层是Agent提供灵活性和智能型。

workflow是骨架，Agent是workflow的大脑。
workflow没什么创造力，Agent有，但是不可控，一起结合，既高效又有智慧。
